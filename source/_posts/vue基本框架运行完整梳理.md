# 0.概念区分
**javascript与typescript的区别**
这部分比较简单，直接摘取ai说明：
- JS（赤手空拳）：它是前端的绝对根基，灵活、动态，但没有类型约束。
- TS（穿上铠甲）：它是 JS 的超集，在 JS 的基础上加上了“静态类型系统”。
最后浏览器只认 JS，TS 最终也要被翻译成 JS。

**node.js的作用**
node.js是一个运行时环境，它让javascript不仅限于操纵前端，还让它有了写后端、写脚本的能力。

**npm nvm pnpm**
- NVM：管理node.js环境的工具
- NPM：Node.js包管理器，用于下载node.js的依赖包
- PNPM： 针对 NPM 的痛点进行升级。利用硬链接技术，速度极快，极省硬盘。

**vue与react**
两个工具的诞生都是为了解决一个痛点：使用原生js或ts语言写项目维护困难，于是引入了组件式开发的工具。
- Vue： 尊崇“关注度分离”，把 HTML/JS/CSS 抱团写在 .vue 文件里。官方全家桶（路由、状态管理）非常完善，上手极其平缓。
- React： 尊崇“万物皆可 JS”，开创了 JSX 语法。官方只做核心视图层，其他全靠社区生态，自由度极高，适合逻辑极复杂的巨型项目。

**node.js与next.js**
当我们用react做好了纯前端网页，但是我们想要更快的首屏加载速度，或者想顺便把后端接口也写了，该怎么办？
- Node.js：它是最底层的 JavaScript 运行环境（发动机）。
- Next.js：它是基于 React 封装的全栈 Web 框架。它的底层必须依赖 Node.js 环境来运行。它自带了服务端渲染（SSR）、路由系统等高级功能。

# 1.创建vue项目的具体步骤
**pnpm create vue@latest**
该命令使用pnpm包管理器创建一个最基本的vue网页应用框架，是项目的起点
创建之后会有默认的文件与文件夹，下面逐一说明这些文件与文件夹的用处
* **`.vscode/`**
* **作用：** 存放当前项目在 VS Code 编辑器中的专属配置（比如团队的代码格式化规则、推荐安装的插件等）。有了它，团队里所有人用 VS Code 打开项目时，编辑器的行为就能保持一致。

* **`dist/`**
* **作用：** **打包输出目录**（Distribution 的缩写）。当你运行 `npm run build` 准备把项目部署上线时，Vite 会把所有代码压缩、混淆，生成最纯净的 HTML/CSS/JS 文件放在这里。这个文件夹里的内容才是最终运行在服务器上的。

* **`node_modules/`**
* **作用：** **依赖包存放处**。你项目里用到的所有第三方库（比如 Vue、Vite、各种插件）下载下来后都存在这里。这个文件夹通常巨大无比，**千万不要手动修改它，也不需要把它提交到 Git**。

* **`public/`**
* **作用：** **静态资源公共目录**。存放在这里的资产（如网站图标 `favicon.ico`、不需要经过 Webpack/Vite 编译的纯图片或特殊脚本）会原封不动地被复制到 `dist` 根目录下。可以通过根路径 `/` 直接访问。

* **`src/`**
* **作用：** **源代码目录**（Source 的缩写）。这是你**最核心的工作区**，95% 以上的代码（组件、页面、样式、图片、逻辑等）都写在这里面。

* **`.gitignore`**
* **作用：** Git 忽略配置文件。用来告诉 Git 哪些文件/文件夹**不需要**被纳入版本控制（比如巨大的 `node_modules/`、打包出来的 `dist/`，或者存有敏感密码的 `.env` 文件）。

* **`index.html`**
* **作用：** **项目的单页面入口文件**。现代前端应用（SPA）整个项目其实只有一个 HTML 页面，所有的页面切换和动态内容都是靠 JS 挂载到这个 HTML 的 `<div id="app"></div>` 节点上的。在 Vite 项目中，它直接放在根目录。

* **`jsconfig.json`**
* **作用：** JavaScript 项目配置文件。主要用来给编辑器（如 VS Code）提供智能代码提示。比如配置了 `@` 符号代表 `src/` 目录，这样你在写 `import` 路径时，输入 `@/` 编辑器就能自动联想。

* **`package.json`**
* **作用：** **项目的“身份证”与控制中心**。记录了项目的名称、版本、运行脚本命令（如 `dev`、`build`），以及项目依赖了哪些第三方库。是每一个前端项目都必须有的核心文件。

* **`pnpm-lock.yaml`**
* **作用：** **依赖版本锁定文件**。由 pnpm 自动生成。它精确记录了你安装的每一个第三方库的具体版本和依赖关系，确保团队中其他人在执行 `pnpm install` 时，安装出来的代码一模一样，避免“在我的电脑上明明是好的”这种玄学问题。

* **`README.md`**
* **作用：** 项目说明文档。使用 Markdown 语法编写。通常用来写项目的启动步骤、开发规范、作者信息等，是给团队其他成员或未来的自己看的“说明书”。

* **`vite.config.js`**
* **作用：** **Vite 构建工具的配置文件**。你可以在这里给项目配置开发服务器的端口、配置打包规则、设置跨域代理（Proxy）、或者引入各种 Vite 插件来增强项目功能。

**pnpm build**
注意，并不是pnpm直接运行这个代码，它只是一个传话筒
它首先pnpm会去package.json文件里查找pnpm build命令对应的代码
如"build": "vite build"，或者"build": "bash ./script/build.sh"
然后运行对应的代码

首先，会读取package.json下载项目对应的依赖库
在执行编译功能，将项目编译为浏览器看得懂的.js .css文件，存放在./dist文件夹里

**pnpm run dev**
pnpm同样是传话筒，会去找dev对应的代码
在我的项目里"dev" : "vite"
这条命令会在本地运行一个实时刷新的服务器
vite服务器是实时编译的，也就是浏览到哪个页面，vite就会去，找对应的如app.vue, xxx.vue组件，编译后发送给浏览器
就跳过了漫长的编译时间
