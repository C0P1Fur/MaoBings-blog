## 0.前置知识
**QT与SFML的区别**
一句话总结：
QT是一个侧重界面布局、业务逻辑与跨平台应用的**完整应用框架**（含GUI、网络、数据库等），而SFML是一个专注于2D/3D图形渲染、游戏输入和音频处理的**轻量级多媒体库**
建议：
想通过折腾底层逻辑来提升编程内功，选 SFML；想快速做出有专业界面的实用工具，选 Qt

最后得出结论，我们提升编程能力可以通过开发游戏，而开发游戏则最好使用SFML入门，搞懂底层原理

## 1.SFML入门案例
**给VS2022配置SFML库**
Visual Studio 2022 没有内置 SFML 库
VS 2022 默认只包含了微软自家的开发工具。SFML 是一个第三方库，需要你手动下载并配置

这里我们选择手动链接外部库的方式配置SFML
下载完SFML的库文件后将它放进某个Libraries文件夹里，并通过名称+版本标示库

- 第一步：设置头文件路径
    - 这是为了让 VS 明白 #include <SFML/Graphics.hpp> 到底指向硬盘里的哪个文件
    - 在全局附加包含目录 (Additional Include Directories)中，添加SFML库的include文件夹
- 第二步：设置库文件路径
    - 这是为了让VS知道lib文件放哪
    - 附加库目录 (Additional Library Directories) 中，添加SFML的lib文件夹
- 第三步：输入具体库文件名
    - 光告诉 VS 文件夹在哪还不够，还得告诉它具体要用哪几个 .lib 文件
    - 附加依赖项 (Additional Dependencies) 中，根据你的运行模式手动输入需要的库文件名
- 第四步：防止dll文件
    - 将SFML库的dll文件，全部粘贴到项目输出.exe文件的同级目录下

**.lib文件和.dll文件的区别**
总结：简单来说，.lib 文件是给编译器看的，而 .dll 文件是给操作系统看的
在 C++ 开发中，程序要经历两个主要阶段：
- 编译链接阶段（VS 内部）：
当你按下“生成解决方案”时，VS 需要知道 SFML 里的函数长什么样、怎么调用。这时候它读取的是 .lib 文件。如果配置正确，它会生成一个 .exe 文件
- 运行阶段（Windows 桌面）：
当你双击运行那个 .exe 时，Windows 接管了程序，它发现你的代码里调用了“画一个圆”的函数，但这个函数的具体实现代码并没有包含在 .exe 里面，而是留在了一个外部的 .dll (Dynamic Link Library，动态链接库) 文件里

**SFML入门案例**
```
#include <SFML/Graphics.hpp>

int main() {
    // 1. 创建一个 800x600 的窗口
    sf::RenderWindow window(sf::VideoMode(800, 600), "My SFML Game");

    // 2. 创建一个图形对象（绿色的圆）
    sf::CircleShape shape(50.f);
    shape.setFillColor(sf::Color::Green);
    shape.setPosition(375.f, 275.f);

    // 3. 游戏主循环
    while (window.isOpen()) {
        // --- A. 事件处理 (Events) ---
        sf::Event event;
        while (window.pollEvent(event)) {
            if (event.type == sf::Event::Closed)
                window.close();
        }

        // --- B. 逻辑更新 (Update) ---
        // 这里可以写 shape.move(0.1f, 0.f); 让圆动起来

        // --- C. 渲染绘图 (Draw) ---
        window.clear();          // 清除上一帧
        window.draw(shape);      // 画出现在的图形
        window.display();        // 显示在屏幕上
    }

    return 0;
}
```

注意，上述是旧版本的测试代码
**新版本测试代码**
```
#include <SFML/Graphics.hpp>
#include <iostream>

int main() {
    // 1. 创建渲染窗口 (SFML 3.x 依然使用 VideoMode)
    // 注意：SFML 3 引入了更多显式的构造方式，但这种写法依然通用
    sf::RenderWindow window(sf::VideoMode({800, 600}), "SFML 3.1.0 Test");
    window.setFramerateLimit(60);

    // 2. 创建一个圆形状
    sf::CircleShape shape(50.f);
    shape.setFillColor(sf::Color::Green);
    shape.setOrigin({50.f, 50.f}); // 设置原点在圆心
    shape.setPosition({400.f, 300.f});

    std::cout << "SFML Window is running..." << std::endl;

    // 3. 游戏主循环
    while (window.isOpen()) {
        // 事件处理 (SFML 3 推荐使用这种轮询方式)
        while (const std::optional event = window.pollEvent()) {
            // 关闭窗口事件
            if (event->is<sf::Event::Closed>()) {
                window.close();
            }
            
            // 按键按下事件
            if (const auto* keyPressed = event->getIf<sf::Event::KeyPressed>()) {
                if (keyPressed->code == sf::Keyboard::Key::Escape) {
                    window.close();
                }
            }
        }

        // 4. 渲染逻辑
        window.clear(sf::Color::Black); // 清屏（黑色）
        window.draw(shape);             // 画圆
        window.display();               // 显示内容
    }

    return 0;
}
```

## 998.Adventurer冒险者游戏开发
1. 拟游戏需求文档
在文档里把游戏最基础的玩法与逻辑写清楚，可以使用AI辅助写
2. 将需求文档丢给AI
千万不要直接把整个文档丢给 AI 让它写完整代码，那绝对会演变成一场灾难。
最科学的协作流程是：“结构先行，模块拆解，逐个击破”。
    1. 让 AI 做“架构师”（不要写具体逻辑）
    2. 让 AI 写“骨架”（头文件）
    3. 分功能模块实现（最核心的一步）
    4. 由你来“手动组装”

所以，可以直接将文档发送给AI，并说：
请帮我分析这个需求，并设计出项目的文件夹结构和类清单。暂时不需要写代码。


## 999.学习过程中的补充知识
**MIT与GNU的区别**
- MIT 协议（极致的宽容）：
它的核心逻辑是：“拿去用吧，只要别告我就行。” 它几乎不对使用者做任何限制。你可以修改它、闭源它、甚至把它拿去卖钱

- GNU GPL 协议（传染性的自由）：
它的核心逻辑是：“自由是属于代码的，谁也别想独占。”
它具有**“传染性”**。如果你用了 GPL 的代码并进行了修改或集成，那么你的整个项目也必须开源，并且必须同样使用 GPL 协议
